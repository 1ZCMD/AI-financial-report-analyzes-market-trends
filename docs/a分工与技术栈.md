# AI 金融报告分析市场走势 · 分工与技术栈（按实习任务书 V2）

> 依据：《AI金融报告分析市场走势(1).docx》任务书 + 现有 9,330 份样例数据 + Navicat 的 nailong（MariaDB 10.4）连接
> 约束：4 人（1 队长）、5～6 天、**开发过程禁用 AI**、必须走「需求 → 设计 → 评审 → Git → 开发 → 代码审核 → 测试」流程
> 结论：**能做，但必须换一套更轻的技术栈，并把"规则优先、模型兜底"作为核心设计。**

## 1. 系统长什么样（一句话 + 一张图）

把数据库里的研报文章，变成"某品种一段时间内机构看多/看空的一致性"图表。

```
源库 article 表（待确认） ┐
data1/data2 文件（兜底）  ┴→ ① 统一进 raw_article 表
        ↓
② 提取正文：HTML(lxml) / PDF(pdfplumber) / PNG、扫描件(Tesseract OCR)
        ↓
③ 清洗：去页眉页脚、免责声明、分析师介绍，截断 8000 字
        ↓
④ 规则抽取：品种词典 + 方向词 + 否定词 → 命中直接入库
        ↓ 未命中 / 冲突 / 置信度低
⑤ 大模型兜底：公司 AI 接口（SSE）→ JSON → 入库
        ↓
⑥ 指标计算：按"品种 × 交易日"统计多空平家数 → 一致性预期指数
        ↓
⑦ FastAPI 5 个接口 → ⑧ Vue3(CDN)+ECharts 看板
```

## 2. 技术栈：只留 10 样，全部能手写

| 层 | 选型 | 大白话 | 在项目里干什么 | 谁主用 | 学习量 |
|---|---|---|---|---|---|
| 语言 | **Python 3.12** | 写脚本的语言 | 解析、规则、调模型、算指标 | 全员 | 会基础语法 |
| HTML 解析 | **lxml** | 从网页里抠文字 | HTML 研报转正文 | B | 半天 |
| PDF 解析 | **pdfplumber** | 从 PDF 里抠文字 | 文本层 PDF 转正文 | B | 半天 |
| 图片 OCR | **Tesseract 5 + pytesseract + Pillow**（中文包 chi_sim） | 把图片里的字认出来 | PNG、扫描版 PDF | B | 1 天 |
| 规则抽取 | **Python re + 自建词典（CSV）** | 按关键词和句式抓观点 | 品种 + 看多/看空/看平 + 证据句 | A | 1 天 |
| 大模型 | **公司 AI 接口（SSE）+ requests** | 让模型做语义判断 | 规则抽不到时兜底 | A | 1 天 |
| 数据库 | **MySQL 8 / MariaDB 10.4 + pymysql** | 很多张 Excel | 存文章、观点、指标 | C | 会 SQL 即可 |
| 后端 | **FastAPI + uvicorn（只写同步 GET）** | 把 Python 函数变成网址 | 给页面提供 5 个接口，自带 /docs | C | 1 天 |
| 前端 | **Vue 3（CDN 引入）+ ECharts 5 + fetch** | 拼页面 + 画图 | 看板 8 个区块 | D | 1 天 |
| 测试/协作 | **pytest + Git/GitHub** | 自动测试 + 代码存档 | 单测、代码审核、合并 | 全员 | 各 1 小时 |

**明确不用**：Node/ npm / Vite / Axios（Vue 用 CDN，免构建）、Docker、Redis、微服务、Spring/Java、登录权限、ORM 框架。理由：6 天 + 禁用 AI，少一个组件就少一类环境问题。

> 如果导师坚持要"Vue 工程化"，把 CDN 版换成 Vue CLI 即可，页面代码不用改——但至少多花半天装环境，建议先用 CDN 版把功能跑通。

## 7. Git 与代码审核规范

**仓库结构（单仓、按"数据流水线阶段"分层）**

```
ai-futures-dashboard/
├── main.py                 # C：FastAPI 入口（接口 + 静态页面）
├── config.py               # C：统一读 .env
├── pipeline/               # 数据流水线
│   ├── source.py           # B：读源库 / 文件
│   ├── extract/            # B：html / pdf / ocr / clean
│   ├── rules/              # A：品种词典、方向词、抽取器
│   ├── llm/                # A：SSE 调用 + Prompt
│   └── pipeline.py         # A/B：串联各阶段
├── db/                     # C：连接、SQL、指数
├── api/                    # C：5 个接口
├── web/                    # D：index.html + app.js + vendor
├── scripts/                # 全员：一次性 / 定时任务
├── tests/                  # C/D：pytest
├── docs/                   # 全员：接口约定
└── data/                   # 不进 Git
```

**为什么这样分**

- 按"流水线阶段"分，不按"前端 / 后端"分：4 个人各自有目录，减少改同一个文件的冲突。
- 依赖单向：`web → api → db / pipeline`，禁止反向 import。
- SQL 只写在 `db/repository.py`；规则和 Prompt 只在 `pipeline/rules|llm`；页面只 fetch 接口。
- 入口只有一个：`main.py`（接口 + 静态页面）；离线任务放 `scripts/`。

**目录归属**：B 管 `pipeline/source.py`、`pipeline/extract/`；A 管 `pipeline/rules/`、`pipeline/llm/`；C 管 `db/`、`api/`、`main.py`、`scripts/`；D 管 `web/`；`tests/`、`docs/` 共用。

**分支**：`main`（可演示）← `dev`（每日集成）← `feature/parse|rule|api|page`。
**提交信息**：`模块: 做了什么`，例如 `extract: 支持 PNG OCR`。
**审核清单**：能跑通？异常处理？命名清楚？没有硬编码密码？SQL 参数化？重复代码？注释说明"为什么"？
**合并**：每天 17:30 前合到 `dev`；D5 合 `main` 打 tag `v1.0`。

## 9. 风险与兜底

| 风险 | 兜底 |
|---|---|
| OCR 准确率低 | 图像预处理（灰度/二值/放大 2 倍）；只保 20 张样例；低置信度标"待复核"，人工校对几条即可演示 |
| 源库类型/表结构未知 | 先按 data1/data2 文件导入自建 `raw_article`；`source_type` 字段预留，拿到源库再换适配器 |
| 没有 PNG 样例 | 向导师要 5～10 张；没有就用研报截图自测，流程保留 |
| "禁用 AI"导致进度慢 | 技术栈已砍到最少；先写测试用例再写代码；结对 + 每天审核 |
| 5 天数据跑不完 | 先跑 3/29 一天（约 400 份）也能演示；D4 再扩 |
| 模型限流/超时 | 规则优先，只有未命中的才调模型；结果按文件哈希缓存 |
| D3 还没端到端 | Plan B：Python 从 MySQL 导出 `data.json`，页面直接读 JSON，砍掉接口也能演示 |

## 10. 答辩分工（3～5 分钟）

- **A（1 分钟）**：背景与需求（为什么做、给谁用）+ 技术选型理由
- **B（1 分钟）**：三种格式怎么提取、OCR 怎么处理、数据质量
- **C（1 分钟）**：数据库表、指数公式、接口
- **D（1.5 分钟）**：现场演示（选品种 → 指数 → 观点 → 排行 → 历史）
- **A（0.5 分钟）**：不足与优化方向
